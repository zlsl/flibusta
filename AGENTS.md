# Repository Guidelines

## Структура проекта и организация модулей

Этот репозиторий содержит Dockerized PHP-зеркало и читалку для контента Флибусты. Основная инициализация PHP и общие помощники находятся в `application/` (`init.php`, `functions.php`, `dbinit.php`, `renderer.php`). Веб-точки входа и статические ресурсы лежат в `application/public/`, включая CSS, JavaScript-читалки, шрифты и endpoint-ы извлечения данных. Функциональные страницы организованы как модули в `application/modules/<name>/` с файлами `index.php` и `module.conf`. OPDS-ленты находятся в `application/opds/`. Утилиты для базы данных и обслуживания проекта расположены в `application/tools/`. Runtime-данные монтируются из `Flibusta.Net/`, `FlibustaSQL/`, `cache/` и `secrets/`; не коммитьте загруженные дампы, архивы книг, сгенерированный кеш и реальные учетные данные.

## Команды сборки, тестирования и разработки

- `docker-compose build`: собирает образы PHP-FPM и PostgreSQL.
- `docker-compose up -d`: запускает PostgreSQL, nginx и PHP-FPM; веб-интерфейс доступен на `http://localhost:27100`, OPDS — по `/opds/`.
- `docker-compose logs -f php-fpm webserver postgres`: показывает логи сервисов при отладке.
- `./getsql.sh` и `./getcovers.sh`: вспомогательные скрипты для получения дампов базы и обложек.
- `./update_daily.sh`: запускает ежедневный сценарий обновления.
- `application/tools/dbinit.sh`: инициализирует или импортирует содержимое базы в контексте контейнера.

## Стиль кода и соглашения об именах

Используйте простой PHP в стиле существующего кода: короткие процедурные файлы, логика конкретного модуля в `application/modules/<module>/`, а общий код в `application/functions.php` только при реальном повторном использовании. Сохраняйте читаемые отступы и стиль соседнего кода; в проекте встречаются табы и отступы в четыре пробела, поэтому при правке придерживайтесь локального стиля. Новые модули называйте директориями в нижнем регистре и добавляйте `index.php` вместе с `module.conf`. Для пользовательских значений предпочитайте подготовленные SQL-запросы с привязанными параметрами.

## Рекомендации по тестированию

Автоматический тестовый фреймворк сейчас не настроен. Проверяйте изменения вручную через Docker Compose, открывая затронутый веб-маршрут, формат читалки или OPDS endpoint. Для проверки синтаксиса PHP запускайте точечный lint, например `php -l application/modules/book/index.php`, в окружении с доступным PHP. Изменения, связанные с базой данных, проверяйте на одноразовом импорте до работы с production-дампами.

## Правила коммитов и pull request

В недавней истории используются короткие повелительные или описательные заголовки, а также много merge-коммитов из pull request. Делайте сообщения коммитов краткими, например `Add error detection to covers download` или `Readme link fixed`. В pull request описывайте измененное поведение, перечисляйте шаги ручной проверки, отмечайте влияние на базу данных или конфигурацию и добавляйте скриншоты при изменениях UI.

## Безопасность и конфигурация

Храните пароли в Docker secrets, например `secrets/flibusta_pwd.txt`, а не в PHP-коде или закоммиченной конфигурации. Проверяйте права на `cache/`, `FlibustaSQL/` и скрипты в `application/tools/`; контейнерам нужен доступ на запись или выполнение, как описано в `README.md`.
